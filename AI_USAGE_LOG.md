## 🤖 Assistant *(2026-08-22T21:43:51Z)*

I see you have `make data-large` running right now! While that finishes, here is exactly what `make submission` will do under the hood.

When you run `make submission`, it triggers the `generate_predictions.py` script 4 times to create 4 different zip files:
1. MIND using the Lexical (BM25) Retriever
2. MIND using the Semantic (BERT/FAISS) Retriever
3. EB-NeRD using the Lexical Retriever
4. EB-NeRD using the Semantic Retriever

For each of those 4 runs, the script performs the following process:

### 1. Memory-Efficient Batch Processing
The test sets are absolutely massive (EB-NeRD has 13.5 million impressions). If we tried to load all of that into RAM at once, Python would crash. The script uses PyArrow to stream the parquet files and process them in small "row groups" (batches) so that your RAM usage stays perfectly flat.

### 2. Scoring the Candidates
For every single impression (a moment when a user was shown a list of candidate articles), the script:
- Reads the user's `history` of clicked articles.
- Formulates a query (for BM25, it combines the titles; for Semantic, it takes the average embedding of the history).
- Takes the `article_ids_inview` (the candidates) and **scores only those specific articles** against the user's query.

### 3. Ranking
Once it has the scores (e.g., BM25 scores or Cosine Similarities), it sorts the candidates from highest score to lowest score and assigns them a 1-indexed rank (1 = best match, 2 = second best, etc.). 

### 4. Formatting for Codabench
The script formats the output exactly according to the strict guidelines in the `.txt` files provided by the datasets. It outputs a line that looks like this:
`139350 [3,2,4,1]`
*(Meaning for impression `139350`, the 4th candidate was the best match, the 2nd was second best, etc.)*

### 5. Zipping
Codabench is very strict about zip files—if you include a folder inside the zip, it will fail. The script automatically creates the text file (`prediction.txt` for MIND, `predictions.txt` for EB-NeRD), drops it directly into a fresh `.zip` file without any nested folders, and then deletes the raw text file to save your disk space.

Once it's done, you will have 4 clean `.zip` files in `outputs/submissions/` that are ready to be uploaded straight to the Codabench platforms!
